4.1 Programming Basics

Programming

Writing instructions that a computer can execute. Human-readable source code is translated or interpreted into instructions ultimately executed by the CPU.

Source Code

Human-readable text written in Python, C, Java and other languages.

Machine Code

CPU-level binary/instruction-set operations directly executed by a processor.

Assembly

Low-level mnemonics such as MOV, ADD and JMP that closely represent machine instructions.

Compiler

Translates source before execution and generally creates executable/machine-code output. Compile-time errors can be caught early. C, C++, Go and Rust are common compiled languages.

Interpreter

Executes source through a runtime interpreter/VM. Errors can appear at runtime. Python, JavaScript, Ruby and PHP use runtime interpretation systems.

Assembler

Translates assembly language into machine code.

Runtime

Environment in which a program executes, including libraries, memory management and error handling.

Syntax

Language grammar. Invalid syntax produces syntax errors.

Logic

Program reasoning and flow. Logic errors can run successfully while producing wrong results.

Debugging

Finding/fixing bugs with logging, breakpoints and tools such as pdb, gdb and x64dbg.

Cybersecurity relevance

Reverse engineers inspect assembly and machine code to understand malware; exploit researchers study memory and input handling; security teams automate work with Python, Bash and PowerShell.

4.4 Bash Scripting

Shell and Bash

A shell is a command-line interpreter. Bash (Bourne Again Shell) is a common Linux shell and scripting language for administration and security automation.

Exit codes

$? contains the previous command status: 0 normally means success and non-zero means failure. Command substitution uses $(command) (backticks are legacy).

#!/bin/bash domain="$1" ts=$(date +%Y%m%d_%H%M%S) report="recon_${ts}.txt" [[ -z "$domain" ]] && { echo "Usage: $0 domain"; exit 1; } { echo "WHOIS"; whois "$domain" 2>/dev/null || true; echo "DNS"; dig "$domain" 2>/dev/null || true; echo "NMAP"; nmap -T3 --top-ports 20 "$domain" 2>/dev/null || true; } > "$report" echo "Saved $report"
Script permissions and safety

Use chmod +x script.sh, run ./script.sh or bash script.sh, and use sudo only when necessary. Quote variables, validate arguments, avoid unsafe eval, and test in an authorized lab.

Execution Policy

Execution Policy is not a security boundary. Attackers may try powershell -ExecutionPolicy Bypass -File script.ps1; defenders need application control, endpoint security, least privilege and logging.

JavaScript

Browser scripting language essential to web security. Understanding JavaScript helps explain DOM behavior, client-side validation, cookies, APIs and XSS.

const MAX=100; let name="alice"; function greet(user){ return "Hello "+user; } const arrow=(user)=>`Hello ${user}`; const user={name:"alice",age:25,isAdmin:true}; const items=[1,"hello",true]; items.push("new"); console.log(user.name,items.length,arrow(name));

var / let / const

var is legacy function-scoped syntax; prefer let for reassignment and const for bindings that should not be reassigned.

Objects

Key-value properties accessed as user.name or user["name"].

Arrays

Ordered values with push, pop, shift, unshift, map, filter, forEach, find, includes, indexOf and length.

DOM

Browser representation of HTML as objects. Unsafe innerHTML with untrusted input can create XSS.

Events

click, submit, keypress, load and other interactions trigger handlers.

Browser security

JavaScript runs in a sandbox; same-origin policy restricts cross-origin reads.

Client-side trust boundary

Users can inspect and modify frontend code. Never trust client-side validation or store secrets in JavaScript. Authorization must be enforced server-side.

console.log(document.cookie); localStorage.setItem("theme","dark"); console.log(localStorage.getItem("theme")); localStorage.removeItem("theme");
fetch("https://example.com/api/data") .then(r=>{if(!r.ok)throw new Error(`HTTP ${r.status}`);return r.json();}) .then(data=>console.log(data)) .catch(err=>console.error(err));
XSS

Cross-Site Scripting causes attacker-controlled script to execute in a victim browser. HttpOnly cookies cannot be read by JavaScript; safe DOM APIs, output encoding and CSP reduce risk. Avoid placing sensitive tokens in localStorage when safer designs are available.

4.7 SQL

SQL / RDBMS

SQL is the standard language for relational databases. A DBMS stores, retrieves and enforces rules; an RDBMS organizes related data into tables connected by keys. Common systems include MySQL, PostgreSQL, SQLite, Oracle and SQL Server.

ConceptMeaning
TableRows and columns representing an entity
RowOne record
ColumnOne field
Primary KeyUnique identifier; not NULL
Foreign KeyReferences another table key
RelationshipsOne-to-one, one-to-many, many-to-many
SELECT * FROM users; SELECT username,email FROM users; SELECT DISTINCT role FROM users; INSERT INTO users(username,email,password_hash) VALUES ('alice','alice@example.com','hash'); UPDATE users SET email='new@example.com' WHERE id=5; DELETE FROM users WHERE id=5; SELECT * FROM users WHERE role='admin'; SELECT * FROM users WHERE email LIKE '%@gmail.com';
SELECT * FROM users ORDER BY created_at DESC; SELECT role,COUNT(*) FROM users GROUP BY role; SELECT users.username,orders.product FROM users INNER JOIN orders ON users.id=orders.user_id; SELECT username FROM admins UNION SELECT username FROM users; SELECT * FROM users WHERE id IN (SELECT user_id FROM orders WHERE amount>1000);
CRUD

Create=INSERT, Read=SELECT, Update=UPDATE, Delete=DELETE. These four operations appear throughout web applications.

SQL Injection

SQLi occurs when untrusted input changes SQL syntax. A vulnerable login might concatenate input: SELECT * FROM users WHERE username = '[INPUT]' AND password = '[INPUT]'. A classic lab payload ' OR 1=1-- can make the condition true and comment out the rest.

4.8 Git & Version Control

Git

Distributed version control system. Each clone can contain history, enabling tracking, branching, merging, comparison and rollback. Git was created by Linus Torvalds in 2005 for Linux kernel development.

Repository

Directory tracked by Git; .git stores repository metadata and history.

Version control

Records changes so versions can be compared and recalled.

Local repository

Your local history and commits.

Remote repository

Shared repository hosted on GitHub/GitLab.

git init git clone https://github.com/user/repo.git git status git add file.py git add . git commit -m "Add port scanner script" git log --oneline git log --graph --oneline git diff git diff --staged
git branch feature-scanner git switch feature-scanner git switch -c feature-logging git branch git switch main git merge feature-scanner git pull origin main git push origin main git push -u origin main
Branching and merging

Branches isolate work. Merge combines histories and may create conflicts if the same lines changed. Pull integrates remote work; push publishes local commits.

# .gitignore __pycache__/ *.pyc .env node_modules/ *.log .idea/ .vscode/
Git security considerations

Never commit passwords, API keys, private keys or credentials. Use environment variables/secret management and ignore .env. Public repositories are searched for secrets. Removing a secret from the latest file does not erase it from history. An exposed /.git/ directory can leak source and history. Review pull requests and consider signed commits.

Cybersecurity portfolio

Use GitHub for scripts, lab notes, sanitized sample data, detection content and READMEs. Only publish work you understand and can explain.
