3.1 OS Fundamentals

An operating system (OS) is the core software layer that manages computer hardware and provides controlled services to applications and users. It makes hardware usable without requiring every application to understand the details of CPUs, memory chips, disks, and devices.

Definition — Operating SystemAn OS is system software that manages hardware resources, provides common services to programs, controls execution, and enforces boundaries between users, applications, and privileged system components.

OS Functions

FunctionWhat it doesSecurity importance
Process managementCreates, schedules, pauses, resumes, and terminates processes and threads.Prevents uncontrolled resource use and supports process isolation.
Memory managementAllocates RAM, maintains virtual address spaces, maps pages, and reclaims memory.Separates processes and limits accidental or malicious memory access.
File managementOrganizes files/directories and controls access, metadata, and storage.Permissions and ACLs protect sensitive data.
Device managementCoordinates keyboards, disks, network adapters, displays and other hardware through drivers.Restricts privileged hardware access and supports trusted drivers.
SecurityAuthenticates users, authorizes actions, isolates processes, audits events, and applies security policies.Forms the host-security boundary.
NetworkingProvides protocol stacks, sockets, routing interfaces, name resolution and network services.Enables host firewalls, network controls and secure communications.

OS Components and Kernel

Typical components include the kernel, device drivers, memory manager, process scheduler, file-system layer, networking stack, security subsystem, system libraries, shells and user applications. The kernel is the privileged core: it mediates access to CPU, memory, devices and protected operating-system data.

Key term — KernelThe kernel runs with high privilege and provides the mechanisms needed to schedule execution, manage memory, handle devices, implement filesystems and enforce access boundaries. A user application normally cannot directly manipulate hardware; it requests services through controlled kernel interfaces.

User Space vs Kernel Space

System Calls

A system call is a controlled request from a user-space program to a kernel service. Common examples include open() to obtain a file descriptor, read() and write() for I/O, fork() to create a process on Unix-like systems, and exec() to replace a process image with another program. The exact API and semantics differ between operating systems.

Hardware Abstraction

Hardware abstraction hides device-specific details behind stable interfaces. A file can be opened through the OS without an application needing to know the exact disk controller commands; similarly, a network program uses sockets rather than directly programming the network card.

3.3 Processes

Definition — ProcessA process is a running instance of a program together with its virtual address space, execution state, resources and operating-system bookkeeping. A program is passive code stored on disk; a process is that code being executed.
ConceptExplanationExample
ProgramExecutable code and associated static resources.A Python script or executable file.
ProcessActive execution context created by the OS.One running instance of Python.
PIDProcess identifier assigned by the OS.ps can show PID 2480.
PPIDParent process identifier.A shell may be the parent of a command it starts.
Parent/childA process may create another process; the creator is the parent and the new process is the child.A shell launching Python.

Process Tree

Foreground, Background and States

A foreground process is attached to the interactive terminal and normally receives its input there. A background process can continue while the shell is available for other work; Unix shells commonly use &, bg and fg.

Creation, Termination and Scheduling

On Unix-like systems, fork() creates a child process by duplicating the caller's process context; the child normally receives a different PID and execution then continues in both processes. exec() can replace a process's program image. Processes terminate normally by returning/exiting or abnormally because of a signal or error. The scheduler selects runnable processes/threads for CPU time using a policy designed to balance responsiveness, fairness, throughput and priority.

3.4 Threads

Definition — ThreadA thread is an execution path within a process. Threads in the same process share resources such as its address space and open files, while each thread has its own execution state, stack and CPU register context.
AspectProcessThread
MemoryNormally has a separate virtual address space.Shares the process address space with sibling threads.
CostCreation/context switching is generally heavier.Generally lighter because resources are shared.
Crash impactOne process crash is normally isolated from other processes.A fatal fault can terminate the entire process and its threads.
CommunicationIPC is commonly needed: pipes, sockets, shared memory, etc.Shared memory makes communication easy, but introduces synchronization risks.

Multithreading allows multiple execution paths within a process. It improves responsiveness and can exploit multiple CPU cores, but shared state creates races, deadlocks and synchronization complexity.

User threads vs kernel threadsUser-level threads can be managed largely by a runtime/library, potentially making operations fast but depending on the threading model for kernel scheduling and blocking behavior. Kernel threads are known to and scheduled by the OS kernel. Modern systems commonly use kernel-supported threading models.

Thread scheduling determines which runnable thread gets CPU time. The scheduler may consider priority, fairness, affinity and whether a thread is interactive or CPU-bound.

3.5 CPU Scheduling

Preemptive vs non-preemptiveIn preemptive scheduling, the OS can interrupt a running task and give the CPU to another task. In non-preemptive scheduling, a running task generally keeps the CPU until it blocks, terminates, or voluntarily yields.
AlgorithmFull formHow it worksTypePros / Cons
FCFSFirst Come First ServedRuns tasks in arrival order.Non-preemptiveSimple and predictable; can create long waits behind a CPU-heavy task.
SJFShortest Job FirstSelects the task with the shortest estimated CPU burst.Usually non-preemptive; preemptive variant is SRTFGood average waiting time when estimates are accurate; long tasks may starve.
Round RobinRound RobinGives each runnable task a time quantum, rotating through the queue.PreemptiveResponsive and fair; quantum too small causes overhead, too large approaches FCFS.
Priority SchedulingPriority SchedulingChooses a highest-priority eligible task.Can be eitherUseful for critical work; low-priority tasks can starve without aging.

Context Switching

A context switch saves the execution state of one thread/process and restores another. The state can include registers, program counter and scheduling metadata. Switching enables multitasking but consumes CPU time and can disturb caches and translation structures, so excessive switching reduces efficiency.

Memory Hierarchy

Paging, TLB and Page Faults

Paging divides virtual memory into pages and RAM into page frames. The page table records mappings and permissions. The CPU's memory-management hardware checks the TLB first; a TLB hit can avoid a page-table walk. If a referenced page is not currently resident and the OS cannot satisfy the access immediately, a page fault occurs. The OS may load the page from backing storage or terminate the access if it is invalid.

Swapping is the movement of memory contents between RAM and backing storage. Systems may use paging rather than swapping entire processes; heavy paging can cause thrashing, where the system spends excessive time moving pages instead of doing useful work.

Segmentation

Segmentation represents memory as logical regions such as code, data and stack, with each segment potentially having its own size and protection attributes. Modern general-purpose systems rely heavily on paging, although segmentation concepts remain important for understanding memory protection and historical architectures.

Virtual Memory Layout

Security note — Buffer OverflowA buffer overflow occurs when software writes beyond the bounds of an allocated buffer. Depending on the bug and defenses, attackers may corrupt data, crash a process, or influence control flow. Modern systems use defenses such as ASLR, DEP/NX, stack canaries, control-flow protections and safer programming practices, but vulnerabilities can still occur.

3.7 File Management

File and directoryA file is a named object used to store data or represent resources. A directory is a filesystem structure that maps names to filesystem objects. Operating systems provide APIs for creating, opening, reading, writing, renaming and deleting them.

On Linux, an open file is represented to a process by a file descriptor (FD), a small integer referring to an open kernel-managed file object. On Windows, programs commonly receive opaque file handles. Standard Unix descriptors are:

FDNameTypical use
0stdinStandard input
1stdoutNormal output
2stderrError/diagnostic output

Permissions, Ownership and Metadata

File permissions determine which users or groups can read, write or execute an object. Ownership identifies its owner and group. Metadata can include timestamps, size, mode/ACL information, link counts and—in filesystems such as ext4—an inode identifier. Metadata is useful for administration and forensics because changes in timestamps, ownership and permissions can provide investigative clues.

File Locks

Advisory locks work when cooperating programs voluntarily check and honor the lock. Mandatory locks, where supported and configured, can cause the OS to enforce locking against conflicting accesses. Advisory locking is common because it is flexible and easier to reason about across applications.

3.8 Windows Fundamentals

Windows Architecture

The Windows kernel and executive provide privileged operating-system mechanisms, while the Hardware Abstraction Layer (HAL) helps isolate platform-specific hardware details. User mode is intentionally restricted; kernel mode can perform privileged operations. A kernel-mode flaw can have a much larger security impact than an ordinary application flaw.

Registry and the Five Hives

HiveStores
HKLMHKEY_LOCAL_MACHINE — machine-wide configuration, installed software, hardware and system settings.
HKCUHKEY_CURRENT_USER — settings for the currently logged-in user.
HKUHKEY_USERS — loaded user profiles and per-user configuration.
HKCRHKEY_CLASSES_ROOT — merged view used for file associations, COM class registration and related class information.
HKCCHKEY_CURRENT_CONFIG — current hardware profile configuration.

Core Windows Administration and Security Components

Services

Background programs managed by the Service Control Manager. Services can start automatically, on demand, at boot, or under defined triggers.

Processes

Running programs represented by process objects and PIDs. Task Manager and PowerShell can inspect them.

Users & Groups

Local accounts exist on an individual machine; domain accounts are centrally managed in enterprise identity infrastructure. Groups simplify authorization.

Administrator & UAC

Administrators have elevated capabilities. User Account Control (UAC) prompts or mediates elevation so ordinary application execution does not automatically run with full administrative rights. UAC bypass techniques are relevant to privilege-escalation investigations.

Microsoft Defender

Windows security components provide anti-malware and endpoint protections, with capabilities that can include real-time protection, behavioral detection and attack-surface controls.

Windows Firewall

Host-based firewall controls inbound and outbound network traffic according to profiles and rules.

Windows Update

Delivers operating-system and security updates. Timely patching closes known vulnerabilities and reduces exposure.

Event Viewer

GUI for Windows event logs. Investigators commonly examine Security, System, Application and service-specific logs.

Task Manager provides process, performance, startup and user views. Device Manager manages hardware devices and drivers. Disk Management handles volumes, partitions and disks. Task Scheduler runs jobs at specified times/events and is also monitored because attackers can abuse scheduled tasks for persistence. Group Policy centrally or locally enforces configuration and security settings. Local Security Policy controls local password, audit, user-rights and related security settings.

3.9 Windows File System

NTFS

NTFS (New Technology File System) is the primary modern Windows filesystem. It supports large volumes/files, journaling, ACLs, compression, encryption features such as EFS, quotas, links and rich metadata. Its security model makes it important in both Windows administration and forensic analysis.

MFT — Master File Table

Definition — MFTThe Master File Table is a central NTFS structure containing records describing files and directories. MFT records can contain names, timestamps, attributes, security identifiers and references to file data. Investigators can use MFT information to reconstruct file-system activity, although interpretation requires care because timestamps and metadata can be altered.

ACL, DACL and SACL

TermMeaning
ACLAccess Control List: collection of entries describing permissions or auditing.
DACLDiscretionary ACL: defines which users/groups are allowed or denied access.
SACLSystem ACL: defines which access attempts should be audited.

File attributes can mark files as hidden, read-only, system, archived, compressed, encrypted, offline and more, depending on the filesystem and Windows version.

Alternate Data Streams

NTFS supports Alternate Data Streams (ADS), which attach additional named data streams to a file. ADS has legitimate uses, but malware can abuse streams to hide payloads or data from casual directory listings. One detection technique is:

dir /r

Security teams should investigate unexpected streams, their contents, parent files and process activity rather than treating every ADS as malicious.

Environment Variables and Persistence

%PATH% tells Windows where executable files may be searched for; %USERPROFILE% points to the user's profile directory; %TEMP% identifies a temporary-data location. Environment variables can influence program behavior and are worth considering during investigations.

Scheduled tasks run commands at triggers such as boot, login or a time. Startup programs can launch software when a user signs in. Both have legitimate uses but are common persistence locations to review. Software installation changes files, services, registry entries, scheduled tasks and dependencies; administrators should use trusted sources, verify software provenance and monitor privileged installers.

3.11 Linux Fundamentals

Linux Architecture

Linux is built around the Linux kernel, which began in 1991 as a project initiated by Linus Torvalds. The kernel is generally described as monolithic, meaning many core services run in kernel space, while loadable modules allow components such as drivers to be added dynamically.

Shell vs terminalA shell interprets commands and scripts; Bash and Zsh are examples. A terminal is an interface that provides input/output for a shell. In a graphical desktop, a terminal emulator is a GUI application that hosts a shell. CLI uses typed commands; GUI uses graphical controls. Both ultimately request OS services.

Root is the traditional Unix superuser, identified by UID 0. Root can bypass many ordinary permission checks, so using it unnecessarily increases risk. sudo lets authorized users run selected commands with elevated privileges according to policy, commonly configured in /etc/sudoers and included files.

3.18 OS Security

Operating-system security is the practice of protecting the host, its users, processes, data and interfaces against unauthorized access, misuse and compromise. Good host security combines identity, permissions, secure configuration, patching, monitoring, network controls and endpoint protection.

User Accounts

Use individual accounts rather than shared identities. Individual accountability makes actions attributable to a person or service identity and supports auditing.

Authentication

Authentication verifies identity using passwords, keys, certificates, tokens, biometrics or combinations of factors.

Authorization

Authorization determines what an authenticated identity is permitted to do. Authentication and authorization are separate decisions.

Privileges

Privileges are permissions to perform protected operations. Minimize administrative privileges and avoid running services as powerful identities without a need.

Least PrivilegeGive users, processes and services only the permissions they require for their tasks, and no more. Least privilege reduces the blast radius of compromised accounts, applications and services.

Access Control Models

ModelIdeaExample
DACDiscretionary Access Control: resource owners can decide access.Unix file owner/group permissions.
MACMandatory Access Control: centrally enforced labels/policies constrain access.SELinux or AppArmor-style policy enforcement.
RBACRole-Based Access Control: permissions are assigned to roles, then users receive roles.An administrator role can manage servers while a helpdesk role cannot.

Secure Boot, Patching, Firewall and Endpoint Security

Secure Boot verifies trusted boot components through a chain of trust, helping prevent unauthorized bootloaders and some bootkits. Patch management keeps the OS and applications current against known vulnerabilities. A host firewall restricts network exposure. Endpoint Detection and Response (EDR) collects endpoint telemetry and provides detection, investigation and response capabilities.
