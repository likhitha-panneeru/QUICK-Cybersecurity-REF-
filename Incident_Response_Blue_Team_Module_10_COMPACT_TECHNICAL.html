10.1

Blue Team Fundamentals

DEFINITION
Blue Team = defensive security operations: prevent, detect, investigate, contain and recover from attacks.
Core
People + Process + Technology. Preventive controls reduce attack surface; detective controls generate telemetry; response controls contain and recover.
Key concepts
Asset → telemetry → detection → investigation → response. Baseline normal behavior first; investigate deviations rather than treating every event as malicious.
Remember
Blue Team is continuous. A good defense improves after every incident through tuning, hardening and validation.

10.2

SOC Operations

DEFINITION
A SOC centralizes security monitoring, alert triage, investigation, escalation and incident coordination.
Tiers
L1: monitor/triage. L2: investigate, correlate and scope. L3: advanced hunting, detection engineering and malware/forensics. Specialized roles may include threat intelligence, DFIR and detection engineering.
Flow
Telemetry → SIEM/EDR → alert → L1 triage → L2 investigation → L3/escalation → containment → closure.
KPIs
MTTD, MTTR, alert volume, false-positive rate, dwell time and ATT&CK coverage.

10.3

Security Monitoring

DEFINITION
Monitoring converts raw telemetry into visibility about authentication, processes, network traffic, endpoints and cloud activity.
Telemetry
Windows Event Logs, Sysmon, Linux auth/journal, firewall, VPN, DNS, proxy, IDS/IPS, EDR and cloud audit logs.
Baseline
Learn normal users, hosts, login times, process trees, DNS patterns and network destinations. Flag rare or impossible behavior.
Useful signals
Impossible travel, unusual admin activity, new services, encoded PowerShell, repeated authentication failures, beacon-like connections.

10.4

Log Analysis

DEFINITION
Log analysis extracts security meaning from timestamped records produced by systems and applications.
Event vs log
An event is an individual occurrence; a log is a collection/record of events. Telemetry is the broader data stream used for detection.
Method
Normalize time/user/host → filter noise → correlate related events → build timeline → validate with endpoint/network context.
Linux
auth.log commonly records SSH/authentication activity. Useful command: `journalctl -u ssh --since '1 hour ago'`.

10.5

SIEM

DEFINITION
SIEM collects, parses, normalizes, stores and correlates security data to produce searchable detections and alerts.
Architecture
Sources → collectors → parsing → normalization → indexing/storage → correlation → detection → alert → analyst.
Splunk
Search with SPL, create alerts/dashboards and enrich events. Example: `index=wineventlog EventCode=4625 | stats count by user, src_ip`.
Sentinel
KQL example: `SecurityEvent | where EventID == 4625 | summarize count() by Account, IpAddress`.
SPL / KQL
index=wineventlog EventCode=4625 | stats count by user, src_ip | where count >= 10

SecurityEvent | where EventID == 4625 | summarize count() by Account, IpAddress

10.6

Detection Engineering

DEFINITION
Detection engineering turns security hypotheses into repeatable logic that identifies malicious or risky behavior.
Detection types
Signature, IOC, IOA/behavioral, threshold, anomaly and correlation detections.
Good detection
Specific enough to reduce noise, broad enough to catch variants, mapped to ATT&CK, with known data sources and an analyst action.
Tuning
Detect → measure false positives → add context/exclusions → test → deploy → monitor. Never suppress an alert without understanding the trade-off.

10.7

Incident Response

DEFINITION
Incident response is the controlled process for handling confirmed or suspected security incidents.
Lifecycle
Preparation → Identification/Detection → Containment → Eradication → Recovery → Lessons Learned.
Containment
Short-term containment limits damage; long-term containment keeps the environment stable while eradication is prepared.
Evidence
Record actions, timestamps, systems, users and evidence handling. Preserve before destructive remediation when possible.

10.8

Incident Classification

DEFINITION
Classification gives incidents a common type and severity so the SOC can prioritize and escalate consistently.
Types
Malware, phishing, account compromise, brute force/password spraying, credential theft, insider threat, exfiltration, ransomware, web attack and network attack.
Severity
Consider business impact, privilege, scope, persistence, data exposure and active attacker presence—not alert name alone.
Example
One failed login = low signal; hundreds across many accounts from one source = likely password spraying and requires broader scoping.

10.9

Alert Triage

DEFINITION
Triage decides whether an alert is benign, suspicious or a real incident and determines the next action.
Workflow
Alert → assess rule → add user/host/IP context → validate → determine severity → scope → respond/escalate → close with evidence.
Ask
What fired? Why now? Which asset/user? Is the source trustworthy? What happened immediately before/after? Are other hosts affected?
Closure
Close only with a reason, evidence, scope and tuning recommendation when appropriate.

10.10

Investigation

DEFINITION
Investigation connects individual alerts into a defensible incident timeline.
5W1H
Who, What, When, Where, Why, How.
Pivot chain
User ↔ host ↔ process ↔ command line ↔ file/hash ↔ IP/domain ↔ authentication ↔ cloud activity.
Timeline
Start with alert time, expand backward for initial access/persistence and forward for execution, lateral movement and impact.

10.11

Indicators of Compromise

DEFINITION
IOCs are observable artifacts associated with malicious activity.
Types
IP, domain, URL, file hash, filename/path, email address, registry key, mutex, process and User-Agent.
Limit
An IOC has shelf life. IPs/domains can change; hashes are precise but often brittle. Combine IOCs with behavior/TTPs.
Use
Search historical telemetry, block where appropriate, enrich alerts and scope affected assets. Validate context before blocking critical infrastructure.

10.12

Threat Intelligence

DEFINITION
Threat intelligence adds context about threats, campaigns, actors, infrastructure and TTPs.
Levels
Strategic = business risk; operational = campaigns; tactical = TTPs; technical = IOCs.
Standards/tools
STIX models threat information; TAXII transports it. MISP and OTX support sharing/feeds; ISACs provide sector intelligence.
Rule
Intelligence is useful only when it changes a defensive decision: detect, hunt, block, prioritize or investigate.

10.13

MITRE ATT&CK

DEFINITION
ATT&CK is a knowledge base of adversary tactics and techniques used to structure detections, hunts and investigations.
Tactics
Initial Access, Execution, Persistence, Privilege Escalation, Defense Evasion, Credential Access, Discovery, Lateral Movement, Collection, C2, Exfiltration and Impact; Enterprise also includes Reconnaissance and Resource Development.
Examples
T1059 Command/Scripting Interpreter; T1053 Scheduled Task/Job; T1078 Valid Accounts; T1021 Remote Services; T1562 Impair Defenses.
Blue Team use
Map detection → technique → required telemetry → test case → coverage gap.

10.14

Endpoint Security

DEFINITION
Endpoint controls observe and restrict activity on workstations and servers.
AV vs EDR vs XDR
AV focuses mainly on malware prevention/detection. EDR provides endpoint telemetry, process trees and response actions. XDR correlates endpoint with identity, email, network and cloud signals.
Important telemetry
Process creation, parent-child relationships, command lines, network connections, file changes, persistence mechanisms and user context.
Response
Isolate host, terminate process, quarantine artifact, collect evidence and remediate persistence—according to incident procedures.

10.16

Authentication Attack Detection

DEFINITION
Authentication attacks abuse passwords, tokens or identities to gain access.
Patterns
Brute force = repeated attempts against one account. Password spraying = one/few common passwords across many accounts. Credential stuffing = reused credentials from external breaches.
Signals
High 4625 count, many users from one source, unusual geography/device, privileged account login, new MFA patterns and successful login after many failures.
Response
Validate source, scope affected accounts, reset/disable as appropriate, revoke sessions/tokens, enforce MFA and investigate successful access.

10.17

Malware Analysis

DEFINITION
Defensive malware analysis determines what a sample is doing and produces actionable detections.
Static
Hash, strings, metadata, imports, signatures and embedded indicators without executing the sample.
Dynamic
Execute in an isolated lab and observe processes, files, registry, network and persistence.
Outputs
IOCs, behavioral detections, YARA rules, ATT&CK mappings and remediation guidance. Memory analysis can reveal injected code, processes and artifacts.

10.18

Digital Forensics

DEFINITION
Forensics preserves and analyzes evidence to reconstruct what happened.
Process
Identify → acquire → preserve → analyze → report.
Evidence
Volatile memory, disk images, event logs, browser artifacts, registry, files, network captures and cloud records.
Chain of custody
Document who collected evidence, when, how, where it was stored and any transfers. Preserve integrity with hashing and controlled access.

10.19

Threat Hunting

DEFINITION
Threat hunting proactively searches telemetry for activity that may have bypassed existing detections.
Method
Hypothesis → select data → query/hunt → validate → scope → respond → document.
SPL
`index=wineventlog EventCode=4688 | search CommandLine=*powershell* | stats count by host, user, CommandLine`.
KQL
`DeviceProcessEvents | where ProcessCommandLine has 'powershell' | summarize count() by DeviceName, AccountName`.

10.20

Incident Reporting & Blue Team Operations

DEFINITION
Reporting turns technical findings into an auditable record and feeds lessons back into operations.
Report
Executive summary → timeline → affected assets → root cause → evidence → impact → containment/eradication → recovery → recommendations.
Operational loop
Measure → identify gap → improve detection/control → validate with tabletop/purple-team testing → measure again.
Metrics
MTTD = time to detect; MTTR = time to respond/recover. Also track alert quality, coverage, dwell time and recurring incident causes.
