2.1 Networking Basics

Definition — Network: A network is two or more devices connected so they can communicate and share resources such as files, applications, printers, services, and internet access.

A useful mental model is that a network is a communication system. Endpoints create or consume data; interfaces put data onto a medium; intermediary devices forward it; protocols define how everyone communicates.

Client

Requests a service. A browser requesting a web page is a client.

Server

Provides a service. A web server receives HTTP requests and returns responses.

Host

Any device with an IP address that sends or receives network data.

Node

Any device participating in a network; switches and routers are nodes even when the term host is used more narrowly.

Peer

A device that can act as both client and server. Peer-to-peer systems such as BitTorrent use this model.

Network Interface

A physical or virtual connection point through which a device communicates.

NIC

A Network Interface Card provides network connectivity. An Ethernet/Wi-Fi NIC has a MAC address used at Layer 2.

Protocols

Rules for formatting, addressing, transporting, routing, and interpreting network communication.

Performance Metrics

Cybersecurity relevance: SOC analysts use latency, loss, throughput, and traffic volume as context. A sudden bandwidth spike, periodic low-volume traffic, or abnormal packet loss can help distinguish attacks from ordinary network problems.

2.4 OSI Model

Definition: The Open Systems Interconnection (OSI) model is a seven-layer conceptual framework standardized by ISO to describe network communication. It separates responsibilities so technologies can be discussed and troubleshot consistently.

Memory tricks: Top-down: All People Seem To Need Data Processing · Bottom-up: Please Do Not Throw Sausage Pizza Away

Layer 7 — Application: Network services closest to user applications. HTTP, DNS, SMTP and SSH are common examples. Security work includes application-layer logs, protocol abuse and malicious requests.
Layer 6 — Presentation: Representation, encoding, compression and encryption concepts. TLS protects application communication, while formats such as JPEG and ASCII/Unicode represent data.
Layer 5 — Session: Establishes, maintains, and terminates logical communication sessions. RPC and session-management mechanisms fit here conceptually.
Layer 4 — Transport: End-to-end delivery, ports, segmentation, reliability and flow control. TCP and UDP operate here.
Layer 3 — Network: Logical addressing and routing between networks. IP and ICMP are core protocols; routers operate primarily here.
Layer 2 — Data Link: Local delivery using frames and MAC addresses. Ethernet, Wi-Fi and switches operate here.
Layer 1 — Physical: Signals, bits, cables, fiber, connectors and radio. Hubs and repeaters work at this level.
Cybersecurity relevance: Saying “Layer 3 issue” or “Layer 7 attack” quickly narrows investigation scope. Examples include IP/routing anomalies at Layer 3, MAC/VLAN attacks at Layer 2, and malicious HTTP requests at Layer 7.

OSI vs TCP/IP: Learn both. OSI is a universal language for discussion and troubleshooting (“Layer 3 issue”), while TCP/IP represents the protocols actually implemented across modern Internet-connected systems.

2.6 Ethernet

Ethernet: A dominant wired LAN technology standardized by IEEE 802.3. It defines how data is placed into frames and transmitted over Ethernet networks.
MAC address: A traditional Ethernet MAC address is 48 bits (6 bytes), commonly written as AA:BB:CC:DD:EE:FF. The first 3 bytes identify an OUI associated with a manufacturer; the remaining portion identifies an interface. MAC addresses can be spoofed, so they are not a strong identity mechanism.

Switching Concepts

ConceptExplanation
MAC Address TableA switch learns source MAC addresses and the ports on which they were seen. Unknown destinations are flooded within the relevant Layer 2 scope.
Full DuplexSend and receive simultaneously. Modern switched Ethernet normally uses full duplex and avoids traditional Ethernet collisions.
Half DuplexOne direction at a time. Classic hubs used this model and could experience collisions.
Collision DomainA segment where simultaneous transmissions can collide. A hub forms one shared collision domain; a switch gives each port its own collision domain.
Broadcast DomainThe set of devices that receive a Layer 2 broadcast. A switch normally remains one broadcast domain; routers and VLAN boundaries separate broadcast domains.
MAC spoofing: Tools such as macchanger can change the apparent source MAC. Attackers may use this to bypass weak MAC filtering or complicate tracking. Defenses include stronger authentication, port security, 802.1X, segmentation and monitoring rather than trusting MAC alone.

2.8 Subnetting

Subnetting: Dividing a larger IP network into smaller networks. It improves address efficiency, limits broadcast scope, supports segmentation, and can improve security architecture.

Subnet Mask

A 32-bit IPv4 mask. 1 bits represent the network portion; 0 bits represent host bits. Example: 255.255.255.0.

CIDR

Classless Inter-Domain Routing notation uses a prefix length such as /24.

Network ID

Result of bitwise AND between IP address and subnet mask.

Host ID

The portion used to identify a host inside the subnet.

Subnet ID

The logical subnet identifier created when host bits are borrowed for subnetting.

VLSM

Variable Length Subnet Masking allows different subnet sizes in one address space for efficient allocation.

2.10 ARP

ARP (Address Resolution Protocol): Resolves a known IPv4 address to a MAC address on the local network so a device can build the appropriate Ethernet frame.

ARP cache: A local table of recent IP-to-MAC mappings. View it with arp -a; entries normally expire or are refreshed over time. Gratuitous ARP is an unsolicited ARP announcement, useful during IP changes but also abused by attackers.

ARP spoofing / poisoning: ARP has no built-in authentication. An attacker can send forged replies claiming to own the gateway's IP, causing victims to send traffic through the attacker for a man-in-the-middle position. Common lab tools include arpspoof, ettercap, and bettercap. Defenses include Dynamic ARP Inspection, suitable static ARP entries, segmentation, and encryption such as HTTPS.

2.12 TCP

TCP (Transmission Control Protocol): A connection-oriented transport protocol that provides reliable, ordered byte-stream delivery using acknowledgments, sequence numbers, retransmission, flow control, and congestion control.

TCP Header Fields

Acknowledgment Number32 bitsNext sequence number expected; acknowledges received data.
FlagsControl bitsConnection establishment, termination, reset and other control.
Window Size16 bitsAdvertised receive capacity for flow control.
Checksum16 bitsError detection over TCP segment data and header.
FlagMeaningRole
SYNSynchronizeInitiates a connection and synchronizes sequence numbers.
ACKAcknowledgeConfirms receipt.
FINFinishGraceful connection shutdown.
RSTResetImmediately aborts a connection.
PSHPushRequests prompt delivery of buffered application data.
URGUrgentMarks urgent-pointer-related data.

Step 1: Client sends SYN with an initial sequence number. Step 2: Server replies SYN-ACK, acknowledging the client's sequence and providing its own. Step 3: Client sends ACK, confirming the server's sequence. Both sides can now exchange application data.

Flow Control

A sliding-window mechanism lets the receiver advertise how much data it can accept. The sender respects that receive window.

Congestion Control

TCP reduces sending pressure when it detects congestion using mechanisms such as slow start and congestion avoidance.

Retransmission

If expected acknowledgments do not arrive within the appropriate timeout, TCP retransmits missing data.

Termination

Typical graceful close uses FIN→ACK→FIN→ACK. RST abruptly terminates a connection.

SYN flood: An attacker can send many SYN packets without completing the final ACK, leaving the server with numerous half-open connections. SYN cookies, connection limits, rate limiting and upstream protection can reduce this denial-of-service risk.

2.13 UDP

UDP (User Datagram Protocol): A connectionless transport protocol with no handshake and no built-in guarantee of delivery or ordering. Its small overhead makes it useful where low latency or application-controlled reliability matters.
UDP header: Only 8 bytes: Source Port, Destination Port, Length, and Checksum. This is substantially smaller than a typical TCP header.
FeatureTCPUDP
ConnectionConnection-orientedConnectionless
ReliabilityOrdered, acknowledged, retransmittedNo delivery/order guarantee
Speed/overheadHigher overheadLow overhead, often lower latency
Header20+ bytes8 bytes
Flow controlBuilt inNot provided by UDP itself
ExamplesHTTP, email, FTP, SSHDNS, DHCP, streaming, gaming, VoIP
UDP attack patterns: UDP floods can overwhelm targets. DNS and NTP amplification abuse servers that generate responses much larger than requests, often using spoofed source addresses. UDP's lack of a handshake also makes source spoofing easier. Defenses include anti-spoofing, rate limiting, resolver hardening, filtering, and DDoS protection.

2.17 Switching

Layer 2 switching: A switch forwards Ethernet frames using destination MAC addresses. It learns where devices live by inspecting source MAC addresses.
Frame arrives
→
Learn source MAC + port
→
Look up destination
→
Forward or flood

VLAN

A Virtual LAN logically divides one physical switching infrastructure into separate broadcast domains. VLAN 10 and VLAN 20 need Layer 3 routing to communicate.

Access Port

Belongs to one VLAN and commonly connects to an end device. The endpoint normally does not need to know its VLAN tag.

Trunk Port

Carries multiple VLANs between switches or other VLAN-aware devices. IEEE 802.1Q adds a VLAN tag to identify traffic.

Native VLAN

Traffic associated with the native VLAN can be untagged on a trunk. Default VLAN 1 should not be treated as a security boundary.

Inter-VLAN Routing

Traffic between VLANs requires a Layer 3 device, such as a router or Layer 3 switch. Router-on-a-stick uses subinterfaces on one trunk.

STP

Spanning Tree Protocol prevents Layer 2 loops by blocking redundant paths and activating alternatives when topology changes.

Broadcast storm: A switching loop can multiply broadcasts and unknown-unicast traffic until network resources are exhausted. STP is therefore a foundational availability control. VLAN hopping can also exploit poor trunk/native-VLAN configuration; secure VLAN design, explicit trunks and unused-port controls reduce risk.

Dynamic Routing Protocols

RIP

Routing Information Protocol. Uses hop count, has a maximum usable path length of 15 hops, converges slowly, and is largely legacy.

OSPF

Open Shortest Path First. Uses link cost, supports areas, converges quickly, and is common in enterprise interior routing.

BGP

Border Gateway Protocol. Exchanges routes between autonomous systems and ISPs and is fundamental to the global Internet. BGP hijacking is a serious security risk.

Route selection: Routers commonly prefer the longest prefix match; when multiple routes have the same prefix, administrative distance and protocol-specific metrics help determine the preferred route.

2.20 DNS

DNS (Domain Name System): The distributed naming system that translates human-readable domain names into IP addresses and stores other records needed for Internet services.
Domain: A human-readable name such as www.example.com, commonly understood as subdomain + registered domain + TLD. FQDN: A fully qualified domain name identifies a complete DNS name, conceptually including the root.

DNS Resolution

Recursive query: the device asks a resolver to obtain the answer; the resolver does the work. Iterative query: a DNS server asks another server and follows referrals until it reaches an answer.

RecordFull FormPurpose

DNS caching: Devices and resolvers cache answers to reduce latency and traffic. On Windows, ipconfig /flushdns clears the local resolver cache. On Linux, cache-clearing commands depend on the resolver service; for systemd-resolved, systemd-resolve --flush-caches is a commonly encountered command.
DNS threats: DNS spoofing/poisoning can insert false answers and redirect users. DNSSEC provides cryptographic authenticity for signed DNS data. DNS tunneling encodes information in DNS queries/responses to create covert channels or exfiltrate data; defenders can look for unusually long/random domains, abnormal query volume, rare destinations, and beacon-like timing.

2.21 DHCP

DHCP (Dynamic Host Configuration Protocol): Automatically supplies clients with IP configuration such as an address, subnet mask, default gateway, DNS server information, and lease duration.

DHCP lease: An address is normally temporary rather than permanent. Clients renew before expiration; common DHCP behavior begins renewal around 50% of the lease and retries more broadly as expiration approaches.

DHCP Server

Maintains address pools, leases and network options and answers client requests.

DHCP Relay

Forwards DHCP broadcasts between subnets when the DHCP server is elsewhere. Routers/L3 devices commonly provide this function.

Rogue DHCP: An attacker can operate a fake DHCP server and supply a malicious gateway or DNS server, enabling interception or phishing redirection. DHCP Snooping on capable switches restricts trusted DHCP responses to trusted ports.

2.23 Network Analysis

Packet capture: Intercepting and recording network traffic into capture files such as PCAP so analysts can inspect protocols, endpoints, timing, payloads, and anomalies. It is foundational to network troubleshooting and network forensics.
Frame vs Packet: A frame is a Layer 2 unit containing local-link information such as MAC addresses. A packet is a Layer 3 unit carrying IP addressing information. Ethernet frames can carry IP packets.
Promiscuous mode: A NIC in promiscuous mode accepts frames it can observe rather than limiting capture to traffic addressed to itself. In modern switched networks, this does not magically reveal every network conversation; the interface must be positioned where the desired traffic is visible, such as the endpoint itself, a mirror/SPAN port, or an appropriate network sensor.
Wireshark: A widely used free/open-source network protocol analyzer. It can capture live traffic, open PCAP files, decode protocols, and inspect packet fields and bytes.

Core Wireshark Skills

Capture Filters

Filter traffic while capturing using BPF syntax. Examples: host 192.168.1.1, port 80, tcp.

Display Filters

Filter an existing capture. Examples: http, ip.addr==10.0.0.1, tcp.port==443, dns, tcp.flags.syn==1.

Follow TCP Stream

Right-click a TCP packet → Follow → TCP Stream to reconstruct a conversation into a readable stream where protocol contents permit.

Protocol Hierarchy

Statistics → Protocol Hierarchy shows the traffic breakdown by protocol and helps identify unexpected protocols.

Conversations

Statistics → Conversations summarizes communicating endpoints and data volumes.

Expert Info

Analyze → Expert Information highlights retransmissions, errors, warnings and anomalies that deserve investigation.

What to look for:

Port Scans

Many SYN packets toward different destination ports from one source.

Beaconing

Regular periodic outbound connections to the same destination can indicate command-and-control behavior.

DNS Tunneling

Unusually long/random domain labels, high query volume, or repeated traffic to a single external DNS destination.

Large Outbound Transfers

Unexpected sustained outbound traffic can indicate possible data exfiltration.

ARP Anomalies

Multiple ARP replies mapping one IP to different MAC addresses can indicate spoofing or network changes requiring investigation.

Cleartext Credentials

HTTP POST, FTP, and Telnet traffic can expose credentials to anyone who can legitimately capture the traffic.
