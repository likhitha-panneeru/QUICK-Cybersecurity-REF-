Network Security

Technical study reference covering network threats, firewall architecture, IDS/IPS, WAF, VPNs, network attacks, wireless security, segmentation, secure protocols, and monitoring.

7.1

Network Security Basics

ATTACK

— Network Threats (any potential danger to the network's confidentiality integrity or availability — threat actors scanning for open ports, malware spreading across the LAN, insider threats exfiltrating data, DDoS attacks overwhelming services; network threats are constant because networks are the primary pathway for both legitimate communication and attacks; every device connected to a network is both an asset to protect and a potential entry point for attackers).

CONCEPT

Network Attacks (deliberate actions exploiting network vulnerabilities — can target any layer of the OSI model from physical cable tapping to application-layer attacks like SQL injection; categories: passive attacks eavesdropping/sniffing observe traffic without modifying it, active attacks modify intercept or disrupt traffic; attacks covered in detail in section 7.6).

ATTACK

Attack Surface in network context (every open port, every running service, every network-connected device, every user account, every wireless access point, every exposed protocol — the sum of all potential entry points an attacker could use to enter or extract data from the network; a network with 500 devices running 10 services each has a vastly larger attack surface than one with 50 devices running 3 services; reducing attack surface: close unnecessary ports, disable unused services, segment the network, use firewalls, minimize internet-facing services, patch everything).

ATTACK

Network Segmentation definition (dividing a network into smaller isolated segments or zones so that a breach in one segment doesn't automatically compromise the entire network — the principle of containment; if an attacker compromises a workstation in the HR segment they shouldn't be able to reach the finance servers or the production database; covered in detail in 7.8 but introduced here as a fundamental concept).

CONCEPT

Network Hardening (the process of securing a network by reducing its attack surface — disabling unnecessary services and protocols, changing default passwords and configurations, applying patches and firmware updates, implementing strong access controls, configuring firewalls and ACLs, enabling encryption, removing unused accounts, disabling SNMP v1/v2 or switching to v3, disabling Telnet and using SSH, disabling unused switch ports, implementing port security).

7.2

Firewalls

DEFENSE

— Firewall definition (a network security device or software that monitors and filters incoming and outgoing network traffic based on a set of predefined security rules — the most fundamental network security control; acts as a barrier between trusted internal networks and untrusted external networks; examines each packet and decides whether to allow or block it based on rules matching source IP, destination IP, source port, destination port, protocol, and sometimes application-level content; the first line of defense in any network).

CONCEPT

Packet Filtering Firewall (simplest type — examines each packet independently based only on header information: source/destination IP, source/destination port, protocol TCP/UDP/ICMP; makes allow/deny decision per packet with no awareness of connection state; fast but can't detect attacks that span multiple packets or abuse established connections; operates at OSI Layer 3-4; example rule: allow TCP traffic from any source to destination port 80 — this allows HTTP but can't verify the traffic is actually HTTP).

CONCEPT

Stateful Firewall (tracks the STATE of active connections — maintains a state table recording all established connections; when a packet arrives the firewall checks if it belongs to an existing legitimate connection; a response packet is only allowed if there was a corresponding outbound request; much more secure than stateless because it understands the context of traffic — an inbound SYN-ACK is only allowed if the firewall saw the outbound SYN first; can detect and block packets that don't belong to any valid connection; operates at Layer 3-4 with connection awareness; most modern firewalls are stateful).

ATTACK

Stateless Firewall (treats each packet independently — no connection tracking no state table; must have explicit rules for both outbound and inbound traffic including response traffic; easier to bypass because it can't distinguish between a legitimate response and an attacker-initiated connection; legacy concept — packet filtering firewalls are stateless; faster but less secure than stateful).

CONCEPT

Application Firewall / NGFW (Next-Generation Firewall — inspects traffic at the APPLICATION layer Layer 7, not just IP/port; can identify and filter specific applications regardless of port — blocks BitTorrent even if it runs on port 80, allows Slack but blocks Facebook, inspects HTTPS traffic via SSL/TLS decryption; features: deep packet inspection DPI, application awareness and control, integrated IPS, URL filtering, malware scanning, user identity awareness; examples: Palo Alto Networks, Fortinet FortiGate, Cisco Firepower, Check Point; the modern standard for enterprise firewalls).

DEFENSE

Host Firewall (software firewall running on an individual device — protects that specific host; examples: Windows Firewall with Advanced Security wf.msc, Linux iptables/nftables/ufw; controls traffic to and from that specific machine; provides defense-in-depth — even if the network firewall is bypassed the host firewall provides another layer; should be enabled on ALL systems including servers).

CONCEPT

Network Firewall (hardware appliance or dedicated software protecting an entire network segment — sits at the boundary between network zones or between internal network and internet; dedicated device with optimized hardware for high-speed traffic inspection; examples: Palo Alto Fortinet Cisco pfSense; typically rack-mounted in the data center or server room).

Firewall Rules (the policies that define what traffic the firewall allows or blocks; rules are processed in ORDER from top to bottom — first matching rule wins; rule components: action allow/deny, protocol TCP/UDP/ICMP/any, source IP/network, source port, destination IP/network, destination port, direction inbound/outbound; best practice: default deny — block everything by default and explicitly allow only what's needed "allowlisting approach"; implicit deny at the bottom of the ruleset catches anything not explicitly allowed; show example ruleset in code block:

Rule 1: ALLOW TCP from Any to 10.0.0.5 port 443 (HTTPS to web server)
Rule 2: ALLOW TCP from Any to 10.0.0.5 port 80 (HTTP to web server)
Rule 3: ALLOW TCP from 10.0.1.0/24 to 10.0.2.0/24 port 22 (SSH from admin to servers)
Rule 4: DENY TCP from Any to Any port 23 (block Telnet everywhere)
Rule 5: ALLOW UDP from 10.0.1.0/24 to 8.8.8.8 port 53 (DNS queries)
Rule 6: DENY Any from Any to Any (default deny  —  implicit)

Explain each rule and why order matters — if default deny was first nothing would be allowed).

CONCEPT

ACL (Access Control List — in networking context a list of rules on a router or firewall that filters traffic; same concept as firewall rules applied on router interfaces; Cisco routers use ACLs to control traffic flow between interfaces and networks; standard ACL filters by source IP only, extended ACL filters by source/destination IP port and protocol).

CONCEPT

Inbound vs Outbound (inbound = traffic coming INTO the network/interface from outside, outbound = traffic going OUT from the network/interface to outside; firewall rules should filter BOTH directions — inbound rules protect against external attacks, outbound rules prevent data exfiltration malware C2 communication and unauthorized connections; many organizations only filter inbound and ignore outbound — this allows malware to phone home and data to be exfiltrated freely).

Allow vs Deny (allow = permit the traffic to pass through, deny = block/drop the traffic; deny can be: drop silently discard with no response making the target appear offline, or reject send back an error message like ICMP port unreachable informing the sender; drop is more secure for external traffic — doesn't reveal the firewall exists, reject is more useful internally — tells the user/application why the connection failed). SVG DIAGRAM showing firewall placement: External Network/Internet on the left → Firewall in the middle examining packets with magnifying glass icon → Internal Network on the right; show a packet being inspected with labels: Source IP, Dest IP, Source Port, Dest Port, Protocol, and the firewall checking rules and making Allow or Deny decision. Linux firewall commands in code block:

# iptables examples
iptables -L -n -v                                    # list all rules with counters
iptables -A INPUT -p tcp --dport 22 -s 10.0.1.0/24 -j ACCEPT  # allow SSH from admin subnet
iptables -A INPUT -p tcp --dport 80 -j ACCEPT         # allow HTTP from anywhere
iptables -A INPUT -p tcp --dport 23 -j DROP           # block Telnet
iptables -A OUTPUT -p tcp --dport 4444 -j DROP        # block common reverse shell port outbound
iptables -A INPUT -j DROP                              # default deny all other inbound
iptables-save > /etc/iptables.rules                    # save rules

# ufw examples (simplified frontend)
ufw enable                                             # enable firewall
ufw default deny incoming                              # default deny inbound
ufw default allow outgoing                             # default allow outbound
ufw allow 22/tcp                                       # allow SSH
ufw allow from 10.0.1.0/24 to any port 22             # allow SSH from admin subnet only
ufw deny 23/tcp                                        # block Telnet
ufw status verbose                                     # show rules and status

7.3

IDS/IPS

DEFINITION

— IDS definition (Intrusion Detection System — monitors network traffic or host activity and generates ALERTS when suspicious or malicious activity is detected; IDS is PASSIVE — it detects and reports but does NOT block the attack; think of it as a security camera — it sees the burglar and sounds the alarm but doesn't stop them; the SOC analyst receives the alert and investigates; deployed by connecting to a SPAN port or TAP to receive a copy of traffic without being inline).

IDS vs IPS deployment
IDS — out of band
IPS — inline
CONCEPT

NIDS (Network-based IDS — monitors network traffic at strategic points; deployed on network segments to watch all traffic passing through; examples: Snort Suricata Zeek; can see network-wide attacks port scans lateral movement; cannot see encrypted traffic unless SSL/TLS inspection is performed; cannot see attacks that stay within a single host).

DEFENSE

HIDS (Host-based IDS — monitors activity on a specific individual host; watches file system changes, log files, process activity, registry modifications, system calls; examples: OSSEC Wazuh AIDE Tripwire; can detect: file integrity violations unauthorized configuration changes privilege escalation rootkit installation; deployed as an agent on each host; can see what happens inside the host that network IDS misses; complementary to NIDS — use both for defense in depth).

Signature-based Detection (compares traffic or activity against a database of known attack signatures/patterns — like antivirus definitions; effective against KNOWN attacks — if the attack matches a signature it's detected; fast and low false positives for known threats; weakness: CANNOT detect unknown/novel attacks zero-days or attacks that are modified to avoid matching known signatures; requires constant signature updates; example Snort rule in code block:

alert tcp $EXTERNAL_NET any -> $HOME_NET 80 (
    msg:"SQL Injection attempt detected";
    content:"' OR 1=1";
    nocase;
    sid:1000001;
    rev:1;
)

Explain each part: alert action, tcp protocol, source destination, msg alert message, content string to match, sid signature ID).

CONCEPT

Anomaly-based Detection (establishes a BASELINE of normal network behavior then alerts on deviations from that baseline — detects unusual traffic patterns volumes or behaviors; CAN detect unknown/novel attacks and zero-days because it's looking for abnormal behavior not specific signatures; weakness: higher false positive rate — legitimate but unusual activity like a backup job at an unusual time may trigger alerts; requires training period to learn normal behavior; examples: sudden spike in outbound DNS queries, unusual data transfer volumes at 3 AM, internal host scanning other internal hosts, new protocol appearing on the network).

CONCEPT

Heuristic Detection (analyzes the behavior and characteristics of code or traffic to determine if it's potentially malicious — looks at what something DOES not what it IS; sits between signature and anomaly detection; can detect modified variants of known malware and some novel threats; used in next-gen antivirus and advanced IPS).

CONCEPT

False Positive (the system INCORRECTLY identifies legitimate/benign activity as malicious — the alert is wrong there is no actual attack; the biggest operational challenge for IDS/IPS — too many false positives cause "alert fatigue" where analysts start ignoring alerts and miss real attacks; tuning rules and thresholds reduces false positives; example: a legitimate SQL query containing OR is flagged as SQL injection).

ATTACK

False Negative (the system FAILS to detect an actual malicious activity — a real attack passes through undetected; the worst outcome — you think you're safe but you're compromised; caused by: missing signatures for new attacks, attacker evading detection through encoding/fragmentation/encryption, poorly tuned anomaly baselines; no IDS/IPS is 100% — false negatives will occur which is why defense in depth with multiple detection layers is critical).

CONCEPT

Snort (open-source network IDS/IPS — the most widely deployed open-source IDS; created in 1998; can operate as: packet sniffer, packet logger, or full network IDS/IPS; uses signature-based detection with community and commercial rule sets; Snort rules are the industry standard rule format; mode: IDS passive monitoring or IPS inline blocking; current version: Snort 3 rewritten for modern performance; learn at: snort.org, TryHackMe Snort rooms).

CONCEPT

Suricata (modern open-source IDS/IPS/NSM — multi-threaded for high performance on modern hardware outperforms single-threaded Snort; supports Snort rules plus its own enhanced rule format; additional capabilities: protocol identification regardless of port, file extraction from traffic, TLS/JA3 fingerprinting; capable of multi-gigabit traffic inspection; increasingly preferred over Snort for new deployments; learn at: suricata.io, Suricata documentation).

Quick Check — reveal answer
Question: Is an IDS inline or out of band?
Answer: Out of band; it receives a copy of traffic and generates alerts.
7.4

WAF (Web Application Firewall)

DEFINITION

— WAF definition (a security control that monitors filters and blocks HTTP/HTTPS traffic to and from a web application — specifically designed to protect web applications from application-layer attacks that traditional network firewalls cannot detect; operates at OSI Layer 7 understanding HTTP requests and responses; sits between the internet/client and the web server; inspects every HTTP request for malicious patterns before it reaches the application; complements network firewalls — network firewall protects at Layer 3-4, WAF protects at Layer 7).

CONCEPT

Web Traffic Filtering (WAF examines HTTP request components — URL path, query parameters, POST body, headers, cookies — looking for attack patterns; can inspect both the request going to the server and the response coming back to the client; request inspection catches attacks like SQLi and XSS going in, response inspection catches data leaks and error information going out).

CONCEPT

Rules and Signatures (WAFs use rule sets to identify malicious requests; OWASP ModSecurity Core Rule Set CRS is the most widely used open-source WAF rule set — contains rules for OWASP Top 10 attacks; rules can be: signature-based matching known attack patterns, score-based assigning anomaly scores and blocking above threshold, custom rules specific to the application; WAF operating modes: detection mode log but don't block — for testing and tuning, prevention mode actively block malicious requests — production use).

CONCEPT

SQLi Detection (WAF examines input for SQL injection patterns — looks for: single quotes ' that break SQL strings, SQL keywords like SELECT INSERT UPDATE DELETE DROP UNION OR AND in unexpected places, comment sequences -- and /\* used to comment out remaining SQL, semicolons ; used to chain SQL commands, tautologies like OR 1=1 OR 'a'='a', time-based blind SQLi patterns like SLEEP BENCHMARK WAITFOR; example blocked request: GET /search?q=' OR 1=1-- the WAF detects the SQL injection pattern and blocks the request returning 403 Forbidden).

CONCEPT

XSS Detection (WAF examines input and output for cross-site scripting patterns — looks for: script tags <script>, event handlers onclick onerror onload onmouseover, JavaScript protocol javascript:, HTML injection <img src=x onerror=...>, encoded variants %3Cscript%3E, DOM manipulation functions document.cookie document.write innerHTML eval; example blocked request: POST comment body containing <script>alert(document.cookie)</script>).

ATTACK

Rate Limiting in WAF (restricting the number of requests a client can make within a time window — prevents brute-force attacks against login pages, mitigates DDoS at the application layer, prevents automated scraping and enumeration; example: limit login attempts to 5 per minute per IP, limit API calls to 100 per minute per API key; response when exceeded: HTTP 429 Too Many Requests; more sophisticated rate limiting can be per endpoint per user per session not just per IP). WAF examples and deployment: cloud-based WAFs Cloudflare WAF AWS WAF Akamai — easy to deploy as they sit in front of your application in the cloud, good for DDoS protection; on-premise WAFs ModSecurity open-source running as Apache/Nginx module, F5 ASM, Imperva; security note: WAFs CAN BE BYPASSED — attackers use encoding tricks like double URL encoding Unicode characters null bytes, payload obfuscation case variation mixed encoding, fragmentation splitting the payload across parameters, novel attack patterns not covered by rules; a WAF is a LAYER of defense not a replacement for secure coding — fix the underlying vulnerability don't just rely on the WAF to block it; defense in depth: secure code + input validation + parameterized queries + WAF + CSP.

Quick Check — reveal answer
Question: Which OSI layer does a WAF primarily protect?
Answer: Layer 7 (application layer).
7.5

VPN (Virtual Private Network)

Network security architecture
Traffic crosses explicit security boundaries before reaching more trusted assets.
CONCEPT

Remote Access VPN (allows individual users to connect to a private network from a remote location — the user runs a VPN client on their device which connects to the organization's VPN gateway/server; once connected the user's device acts as if it's on the internal network; used by: remote employees, traveling workers, contractors; client software: OpenVPN, WireGuard, Cisco AnyConnect, GlobalProtect; the most common VPN type for end users).

CONCEPT

Site-to-Site VPN (connects two entire NETWORKS together over the internet — creates a permanent tunnel between two VPN gateways at different locations; all traffic between the two networks is automatically encrypted through the tunnel; used by: companies connecting branch offices to headquarters, data center to data center connections; no client software needed on individual devices — the VPN gateways handle everything; transparent to users — they just access resources on the other network as if they were local).

CONCEPT

IPsec definition (Internet Protocol Security — a suite of protocols that provides encryption authentication and integrity at the NETWORK LAYER Layer 3; operates transparently below the application layer — applications don't need to be modified; two modes: Transport Mode encrypts only the payload leaving IP header visible used for host-to-host communication, Tunnel Mode encrypts the ENTIRE original packet and encapsulates it in a new packet used for site-to-site VPNs and remote access; protocols within IPsec: AH Authentication Header provides integrity and authentication but NOT encryption, ESP Encapsulating Security Payload provides encryption integrity and authentication — ESP is what's actually used for VPN encryption; IKE Internet Key Exchange protocol handles the negotiation of security parameters and key exchange before the VPN tunnel is established; IPsec VPN is the traditional standard for site-to-site connections).

CONCEPT

SSL/TLS VPN (uses TLS the same protocol that secures HTTPS to create VPN connections; operates at Layer 4-7 not Layer 3 like IPsec; advantages over IPsec: works through NAT and firewalls easily uses port 443 same as HTTPS, no special client software needed can work through a web browser clientless mode, easier to set up and manage; two types: clientless SSL VPN user connects via browser to a web portal accessing internal web applications, full tunnel SSL VPN client software creates a full tunnel similar to IPsec but using TLS; examples: OpenVPN uses TLS, Cisco AnyConnect, Palo Alto GlobalProtect; increasingly preferred over IPsec for remote access because of firewall friendliness and ease of use).

CONCEPT

Tunneling (the process of encapsulating one protocol inside another — the VPN takes your original network packets wraps them inside encrypted packets and sends them through the tunnel; the outer packet has the VPN server's address the inner encrypted packet has your actual destination; tunneling protocols: IPsec ESP, OpenVPN using TLS, WireGuard using modern cryptography, L2TP Layer 2 Tunneling Protocol often paired with IPsec, PPTP Point-to-Point Tunneling Protocol OBSOLETE AND INSECURE never use; split tunneling: only traffic destined for the corporate network goes through the VPN, internet traffic goes directly — reduces VPN bandwidth load but means internet traffic is unprotected on public WiFi, security tradeoff vs full tunneling where ALL traffic goes through the VPN).

CONCEPT

VPN Encryption (VPN encrypts all data flowing through the tunnel — typically using AES-256 for the symmetric encryption and RSA or ECDH for key exchange; WireGuard uses modern ChaCha20-Poly1305 cipher; the encryption makes intercepted traffic useless without the keys; perfect forward secrecy PFS ensures that compromising long-term keys doesn't compromise past session keys — each session uses unique ephemeral keys).

ATTACK

VPN Authentication (before the tunnel is established both sides must authenticate — verify they're connecting to the right endpoint not an attacker; methods: pre-shared key PSK both sides know the same secret simple but less secure, digital certificates using PKI strongest method used in enterprise, username/password with MFA most common for remote access VPN, certificate plus username/password for maximum security; VPN without proper authentication could be connecting you to an attacker's server — MITM on VPN). Security note: VPN protects data IN TRANSIT between client and VPN server — it does NOT make you anonymous on the internet the VPN server can see your traffic, it does NOT protect against malware or phishing, it does NOT secure the endpoints themselves — a compromised laptop connecting via VPN gives the attacker VPN access to the corporate network; VPN is one layer not a complete security solution.

Quick Check — reveal answer
Question: Which IPsec mode encrypts the entire original packet?
Answer: Tunnel Mode.
7.6

Network Attacks

DEFINITION

— This is the most critical section — understanding these attacks is essential for both offensive pentesting and defensive SOC analysis.

Network security architecture
Traffic crosses explicit security boundaries before reaching more trusted assets.
ATTACK

MAC Flooding (attacker floods a switch with thousands of fake MAC addresses — the switch's MAC address table has limited capacity; when the table is full the switch can't learn new legitimate MAC entries and falls back to hub behavior — broadcasting all frames to all ports; this allows the attacker to sniff all traffic on the switch; tools: macof part of dsniff; defense: port security limiting number of MAC addresses per port, 802.1X port-based authentication, switch hardware with large MAC tables).

ATTACK

DHCP Spoofing (attacker sets up a rogue DHCP server on the network — when devices send DHCP Discover broadcasts the rogue server responds before the legitimate server with a DHCP Offer containing malicious network configuration; the rogue server can provide: attacker's machine as default gateway enabling MITM, attacker's DNS server redirecting all domain lookups to phishing sites, invalid subnet mask isolating the victim; defense: DHCP Snooping a switch feature that designates specific ports as trusted DHCP sources and drops DHCP server messages from untrusted ports).

ATTACK

DNS Spoofing / DNS Poisoning (attacker corrupts DNS resolution so that domain names resolve to attacker-controlled IP addresses — victim types bank.com but is directed to a perfect clone phishing site; DNS cache poisoning: attacker injects fake DNS responses into a resolver's cache so all subsequent queries for that domain return the attacker's IP until the cache entry expires; DNS spoofing on local network: using ARP spoofing or DHCP spoofing to redirect DNS queries to the attacker's DNS server; defense: DNSSEC cryptographically signs DNS records proving authenticity, DNS over HTTPS DoH and DNS over TLS DoT encrypt DNS queries preventing interception, using trusted DNS resolvers, monitoring for unusual DNS responses).

ATTACK

DNS Tunneling (using DNS queries and responses as a covert communication channel to exfiltrate data or establish command-and-control connections that bypass firewalls — since DNS traffic port 53 is almost always allowed through firewalls attackers encode data into DNS queries; data is encoded as subdomains: the query for aGVsbG8=.data.evil.com encodes "hello" in base64 as a subdomain; the attacker's authoritative DNS server for evil.com extracts the data from the query and can send data back in DNS responses; very slow but extremely hard to block without breaking DNS; tools: iodine dnscat2; defense: monitor for unusually long domain names, high volume of DNS queries to unusual domains, DNS queries for non-existent domains with high entropy subdomains, block known DNS tunneling tool signatures).

Man-in-the-Middle attack flow
ATTACK

Packet Sniffing (passively capturing network packets to read their contents — on a shared medium or after performing ARP spoofing/MITM; tools: Wireshark tcpdump ettercap NetworkMiner; what can be captured on unencrypted connections: usernames and passwords in plaintext HTTP FTP Telnet POP3, email content, browsing history, file transfers, any unencrypted data; defense: encryption HTTPS SSH TLS for everything, VPN on untrusted networks, network segmentation, switched networks not hubs, detecting promiscuous mode on the network).

ATTACK

Session Hijacking (attacker steals or predicts a valid session ID to impersonate a legitimate user without needing their credentials — the attacker takes over an authenticated session; methods: stealing session cookies via XSS, sniffing unencrypted session cookies on the network, predicting sequential or weak session IDs, MITM attack capturing the session token; once the attacker has the session ID they set it in their own browser and the server treats them as the legitimate user; defense: HttpOnly and Secure flags on session cookies, HTTPS everywhere, strong random unpredictable session IDs, session expiration, binding sessions to client attributes like IP or User-Agent, regenerating session ID after login).

DEFENSE

DoS / DDoS (Denial of Service / Distributed Denial of Service — overwhelming a target with traffic or requests making it unavailable to legitimate users; DoS: attack from a single source — can often be mitigated by blocking that source IP; DDoS: attack from thousands or millions of sources botnets — much harder to mitigate because legitimate and malicious traffic are mixed and come from everywhere; targets: bandwidth saturation, server resource exhaustion CPU/RAM, application-layer resource exhaustion connections/queries; financial impact: downtime lost revenue reputation damage; defense: DDoS mitigation services Cloudflare AWS Shield Akamai, rate limiting, traffic filtering, anycast distribution, over-provisioning bandwidth, incident response plans).

ATTACK

SYN Flood (TCP-based DoS/DDoS — attacker sends massive numbers of SYN packets initiating TCP handshakes but never sends the final ACK to complete them; the server keeps half-open connections in its state table consuming memory; when the state table is full legitimate users can't establish new connections; the most common network-layer DDoS technique; defense: SYN cookies server doesn't allocate state until handshake completes, increasing backlog queue size, reducing SYN-RECEIVED timeout, firewall rate limiting SYN packets, DDoS mitigation services).

ATTACK

UDP Flood (attacker sends massive UDP packets to random ports on the target; for each packet the target checks for a listening application on that port finds none and sends ICMP Destination Unreachable; this overwhelms the target's processing and bandwidth; effective because UDP is connectionless so spoofed source IPs are trivial; amplification attacks DNS amplification NTP amplification send small queries with spoofed victim source IP to open resolvers which send large responses to the victim amplifying by 50-70x; defense: rate limiting UDP, filtering at upstream provider, disabling unnecessary UDP services).

ATTACK

ICMP Flood / Ping Flood (overwhelming target with ICMP Echo Request packets consuming bandwidth and processing; simple but effective especially with amplification like Smurf attack broadcast ping with spoofed source; defense: rate limiting ICMP, blocking ICMP at firewall for external traffic or rate limiting, DDoS mitigation).

Quick Check — reveal answer
Question: What attack associates an attacker MAC with the gateway IP?
Answer: ARP spoofing / ARP poisoning.
7.7

Wireless Security

DEFINITION

— Wi-Fi (wireless networking technology using radio waves to provide network connectivity; operates on 2.4 GHz and 5 GHz frequency bands with 6 GHz added in Wi-Fi 6E; IEEE 802.11 standard family: 802.11b/g 2.4GHz older, 802.11n Wi-Fi 4 both bands, 802.11ac Wi-Fi 5 5GHz, 802.11ax Wi-Fi 6/6E both plus 6GHz; inherently less secure than wired because radio signals travel through walls and can be received by anyone within range — you can't control who receives the signal).

CONCEPT

SSID (Service Set Identifier — the human-readable name of a Wi-Fi network that appears in the list when you scan; can be hidden SSID broadcast disabled but this is NOT security because probe requests from clients reveal it and tools like airodump-ng see it regardless).

CONCEPT

BSSID (Basic Service Set Identifier — the MAC address of the access point; unique identifier for each AP; visible to any device scanning wireless traffic).

CONCEPT

Access Point / AP (the device that creates the Wi-Fi network — broadcasts SSID, handles client authentication and encryption, bridges wireless clients to the wired network; enterprise environments use multiple APs managed by a wireless controller). Wireless Security Protocols comparison table with columns: Protocol, Full Name, Encryption, Authentication, Key Length, Status, Security Level: WEP (Wired Equivalent Privacy, RC4 stream cipher, shared key or open, 40 or 104 bits, BROKEN/OBSOLETE, none — can be cracked in minutes using tools like aircrack-ng; WEP uses static keys and a flawed initialization vector IV that repeats allowing statistical attacks to recover the key; NEVER use WEP; if you encounter WEP on a pentest it's a guaranteed win).

CONCEPT

WPA (Wi-Fi Protected Access, TKIP Temporal Key Integrity Protocol based on RC4, PSK pre-shared key or 802.1X enterprise, 128 bits, DEPRECATED, weak — TKIP has known vulnerabilities and is deprecated; was a temporary fix for WEP before WPA2 was ready; better than WEP but should not be used).

CONCEPT

WPA2 (Wi-Fi Protected Access 2, AES-CCMP strong, PSK pre-shared key or 802.1X enterprise, 128 bits AES, CURRENT STANDARD widely deployed, strong — the most commonly deployed wireless security standard; WPA2-PSK Personal uses a shared password, WPA2-Enterprise uses 802.1X with RADIUS server and individual credentials per user much more secure; vulnerability: KRACK attack 2017 Key Reinstallation Attack allowed traffic decryption — patched in most devices).

ATTACK

WPA3 (Wi-Fi Protected Access 3, AES-GCMP 256, SAE Simultaneous Authentication of Equals or 802.1X, 192 or 256 bits, NEWEST/RECOMMENDED, strongest — replaces the PSK 4-way handshake with SAE Dragonfly which provides forward secrecy and resistance to offline dictionary attacks even with weak passwords; Protected Management Frames mandatory preventing deauthentication attacks; WPA3-Enterprise uses 192-bit security mode for high-security environments; adoption growing but WPA2 still dominant). Wireless Attacks: Evil Twin (attacker creates a fake access point with the same SSID as a legitimate network — victims connect to the attacker's AP thinking it's the real one; the attacker acts as MITM intercepting all traffic; in a coffee shop the attacker creates "CoffeeShop-WiFi" identical to the real SSID and with a stronger signal; all devices connecting to the evil twin send their traffic through the attacker; tools: hostapd creates the fake AP, dnsmasq provides DHCP and DNS; defense: enterprise 802.1X authentication verifies the AP's identity not just SSID, VPN on public WiFi, verifying certificate warnings, wireless IDS detecting duplicate SSIDs).

ATTACK

Rogue AP (unauthorized access point connected to the corporate network — could be malicious planted by attacker or accidental employee plugging in a personal router; creates an uncontrolled entry point bypassing network security controls; an employee's personal AP might have no encryption allowing anyone to connect to the corporate network; defense: wireless monitoring and rogue AP detection, 802.1X port authentication, NAC network access control, regular wireless surveys, WIDS/WIPS wireless IDS/IPS).

ATTACK

Deauthentication Attack (attacker sends forged deauthentication frames to a client or AP disconnecting them from the network — 802.11 management frames were originally unencrypted and unauthenticated so anyone can send deauth frames appearing to come from the AP; used to: force clients to reconnect to capture WPA handshake for cracking, push clients to connect to an evil twin, cause denial of service disconnecting all clients; tools: aireplay-ng --deauth; defense: WPA3 mandates Protected Management Frames PMF also available optionally in WPA2, 802.11w amendment protects management frames).

TOOLS

Wireless Sniffing / Monitor Mode (putting a wireless NIC into monitor mode allows capturing ALL wireless frames on a channel — not just those addressed to your device; captures: beacons management frames data frames; can see: all SSIDs in range, all connected clients MAC addresses, probe requests revealing what networks devices have connected to before, unencrypted data from open networks or WEP; tools: airmon-ng to enable monitor mode, airodump-ng to capture and display, Wireshark to analyze captures; wireless penetration testing workflow: airmon-ng start wlan0 enable monitor mode → airodump-ng wlan0mon scan for networks → target specific network → aireplay-ng deauth to capture handshake → aircrack-ng crack the handshake with wordlist).

Quick Check — reveal answer
Question: Which Wi-Fi standard replaces the WPA2 PSK handshake with SAE?
Answer: WPA3.
7.8

Network Segmentation

ATTACK

— VLAN recap (Virtual LAN logically segments a switch into separate broadcast domains; devices in different VLANs cannot communicate without a Layer 3 device router or L3 switch; VLANs provide isolation even on the same physical switch; example: VLAN 10 for Finance, VLAN 20 for HR, VLAN 30 for IT, VLAN 40 for Guest WiFi — each segment is isolated; security benefit: if an attacker compromises a device in the Guest VLAN they cannot directly reach Finance servers in VLAN 10).

CONCEPT

Subnetting for segmentation (using different IP subnets for different network segments — combined with router ACLs or firewall rules to control traffic between subnets; 10.10.10.0/24 for servers, 10.10.20.0/24 for workstations, 10.10.30.0/24 for management — firewall rules control which subnets can talk to which and on what ports).

Network security architecture
Traffic crosses explicit security boundaries before reaching more trusted assets.
CONCEPT

Network Zones (organizing the network into trust zones based on security requirements; common zones: Untrusted Zone internet external networks, DMZ semi-trusted public-facing services, Trusted Zone internal network, Restricted Zone sensitive systems databases financial systems, Management Zone admin interfaces network device management OOB out-of-band management; traffic between zones must pass through a firewall with rules appropriate to the trust level; principle: more restrictive rules as you move from less trusted to more trusted zones).

CONCEPT

Microsegmentation (granular segmentation down to individual workloads or applications — not just network segments but isolation between individual servers or containers; traditional segmentation: separate VLANs for departments; microsegmentation: each server or application has its own security policy regardless of network location; if the web server is compromised it cannot reach the database server even though they're in the same subnet — policies enforce communication rules at the workload level; implemented through: software-defined networking SDN, host-based firewalls with central policy management, VMware NSX, cloud security groups; a core component of Zero Trust architecture).

ATTACK

Zero Trust Network (applying Zero Trust principles specifically to network architecture — never assume any device or user on the network is trustworthy regardless of their network location; traditional model: everything inside the corporate network perimeter is trusted = once inside attackers move freely; Zero Trust model: verify every connection regardless of source, segment everything, inspect all traffic even internal, authenticate and authorize every access request, assume breach design networks expecting attackers are already inside; implementation: microsegmentation, identity-based access, MFA everywhere, continuous monitoring and validation, encrypted internal traffic, software-defined perimeters; Google's BeyondCorp is a well-known Zero Trust implementation — eliminated the traditional VPN perimeter in favor of identity and device-based access).

CONCEPT

NAC (Network Access Control — technology that controls which devices are allowed to connect to the network and what level of access they receive; when a device connects NAC checks: is this a known/registered device?, is the OS patched and up to date?, is antivirus installed and running?, does the device meet security policy requirements?; if the device passes: full network access or access to its assigned VLAN; if the device fails: quarantined to a remediation VLAN with limited access to install updates/patches, or denied access entirely; 802.1X is the standard protocol for port-based NAC — requires authentication before granting network access; components: supplicant the device requesting access, authenticator the switch or AP enforcing access, authentication server RADIUS server that verifies credentials; examples: Cisco ISE, Aruba ClearPass, ForeScout; ensures: only authorized compliant devices connect to the network, guest devices are isolated, rogue devices are blocked, BYOD devices are controlled).

Quick Check — reveal answer
Question: What technology provides port-based network admission control?
Answer: NAC, commonly enforced with 802.1X.
7.9

Secure Network Protocols

DEFINITION

— Understanding which protocols are secure and which are insecure is fundamental. The principle: always use the encrypted/secure version of a protocol when available. Secure vs Insecure Protocols comparison table with columns: Insecure Protocol, Port, Secure Replacement, Port, What Changed: HTTP (80, HTTPS, 443, added TLS encryption — all web traffic should be HTTPS), Telnet (23, SSH, 22, plaintext replaced with encrypted channel — Telnet sends EVERYTHING including passwords in plaintext), FTP (21, SFTP or FTPS, 22 or 990, plaintext file transfer replaced with SSH-based or TLS-based encrypted transfer), SNMP v1/v2c (161, SNMPv3, 161, community strings sent in plaintext replaced with authentication and encryption), DNS (53, DNSSEC / DoH / DoT, 53/443/853, unsigned responses replaced with cryptographically signed records and encrypted queries), SMTP (25, SMTP with STARTTLS or SMTPS, 587/465, plaintext email relay replaced with TLS-encrypted submission), POP3 (110, POP3S, 995, plaintext email retrieval replaced with TLS encryption), IMAP (143, IMAPS, 993, plaintext email sync replaced with TLS encryption), LDAP (389, LDAPS, 636, plaintext directory queries replaced with TLS encryption), RDP (3389, RDP with NLA, 3389, added Network Level Authentication requires authentication before session starts).

CONCEPT

HTTPS (HTTP encrypted with TLS — covered in Module 5 but in network security context: enables confidentiality and integrity of web traffic, prevents MITM reading or modifying web content, HSTS header forces browsers to always use HTTPS preventing downgrade attacks, certificate transparency logs all certificates publicly for detection of unauthorized certificates).

CONCEPT

SSH (Secure Shell — encrypted remote command-line access replacing Telnet; provides: encrypted terminal session, key-based authentication stronger than passwords, port forwarding and tunneling, secure file transfer via SCP and SFTP; hardening: disable root login, use key-based auth disable password auth, change default port as obscurity not security, use fail2ban to block brute-force, allow only from specific source IPs).

CONCEPT

SFTP (SSH File Transfer Protocol — secure file transfer over SSH; not the same as FTPS which is FTP over TLS; all commands and data encrypted; replaces insecure FTP).

CONCEPT

IPsec (covered in 7.5 — provides encryption authentication and integrity at the network layer; used for VPN tunnels and secure host-to-host or network-to-network communication).

CONCEPT

TLS (Transport Layer Security — the cryptographic protocol underpinning HTTPS SMTPS IMAPS and most encrypted communication; current version TLS 1.3 faster and more secure than TLS 1.2; TLS 1.0 and 1.1 are deprecated and should be disabled; provides: encryption privacy, authentication server identity via certificates, integrity data hasn't been tampered with; security: disable TLS 1.0/1.1, prefer TLS 1.3, use strong cipher suites, configure perfect forward secrecy PFS).

ATTACK

DNSSEC (DNS Security Extensions — adds cryptographic signatures to DNS records proving they haven't been tampered with; DNS responses include digital signatures verified against the domain's public keys published in DNS; protects against DNS spoofing and cache poisoning; does NOT encrypt DNS queries — for encryption use DNS over HTTPS DoH or DNS over TLS DoT).

CONCEPT

SNMPv3 (Simple Network Management Protocol version 3 — adds authentication with username and password hashed and encryption AES/DES to network management traffic; SNMP v1 and v2c use community strings "public" and "private" sent in plaintext — equivalent to sending passwords in cleartext; always use SNMPv3 or disable SNMP entirely; change default community strings immediately if v1/v2c must be used).

ATTACK

Secure Email (protocols for protecting email in transit: STARTTLS opportunistic TLS upgrade for SMTP — server advertises TLS support and clients upgrade the connection; SMTPS SMTP over implicit TLS on port 465; SPF Sender Policy Framework DNS record specifying which servers can send email for a domain — prevents spoofing from unauthorized servers; DKIM DomainKeys Identified Mail cryptographically signs email headers proving the message wasn't modified in transit and came from an authorized server; DMARC Domain-based Message Authentication Reporting and Conformance policy telling receivers what to do with email that fails SPF/DKIM — reject quarantine or none with reporting; all three SPF DKIM DMARC should be implemented together for comprehensive email authentication and anti-spoofing).

Quick Check — reveal answer
Question: Which protocol replaces Telnet for secure remote administration?
Answer: SSH.
7.10

Network Monitoring

DEFINITION

— Monitoring is the foundation of network security — if you can't see what's happening on your network you can't detect threats, investigate incidents, or respond to attacks.

CONCEPT

Detection is as important as prevention because no preventive control is 100% effective.

TOOLS

Packet Capture (recording raw network traffic for analysis — the most detailed form of network monitoring capturing every byte of every packet; tools: Wireshark GUI-based capture and analysis, tcpdump CLI-based capture especially on servers, tshark command-line Wireshark for scripting; storage: full packet capture generates enormous amounts of data — a 1 Gbps link produces \~450 GB per hour; typically captured strategically: at network perimeters, between security zones, or triggered by alerts rather than always-on; stored in PCAP files for later analysis; used for: incident investigation reconstructing attack timelines, malware communication analysis, forensic evidence, protocol analysis and debugging).

CONCEPT

Flow Data (summarized network connection metadata without the packet payload — records: source IP, destination IP, source port, destination port, protocol, bytes transferred, packet count, timestamps, duration; much smaller than full packet capture — captures WHO talked to WHOM for HOW LONG and HOW MUCH not WHAT was said; think of it as phone records metadata vs recorded conversations content; useful for: detecting anomalous communication patterns, identifying beaconing C2 traffic, tracking lateral movement, capacity planning, long-term traffic trend analysis).

CONCEPT

NetFlow (Cisco's flow data protocol — the original and most widely adopted; alternatives: sFlow sampled flow data, IPFIX IP Flow Information Export the IETF standard based on NetFlow v9; flow data is generated by routers and switches and sent to a flow collector for analysis and storage; tools for analysis: ntopng, SiLK, Elasticsearch with flow plugins, Splunk with flow add-ons).

CONCEPT

Logs (records of events generated by every device and application on the network — firewalls log allowed/denied connections, IDS logs alert events, switches log port events, routers log routing changes, VPN logs connection events, DHCP logs address assignments, DNS logs query records, proxy logs web access, servers log authentication and application events; logs are the PRIMARY source for security monitoring and incident investigation; centralize all logs in a SIEM for correlation and analysis; critical logs to collect: firewall connection logs, IDS/IPS alert logs, authentication logs success and failure, DNS query logs, proxy/web access logs, VPN connection logs, DHCP lease logs, endpoint event logs).

CONCEPT

Alerts (notifications generated when monitoring systems detect potentially malicious or anomalous activity — generated by: IDS/IPS signature matches, SIEM correlation rules matching multiple log events, anomaly detection baseline deviations, threshold violations like 1000 failed logins in 1 minute, custom detection rules; alert management: not all alerts are equal — prioritize by severity and confidence; alert fatigue is real — too many false positive alerts cause analysts to ignore them; tuning: adjust rules to reduce false positives while maintaining detection capability; triage: investigate alerts quickly — is it a true positive or false positive? escalate confirmed incidents).

CONCEPT

Network Baseline (a documented picture of normal network behavior — what normal traffic looks like in terms of: protocols used, traffic volumes by time of day, typical connection patterns, normal source/destination pairs, bandwidth utilization, DNS query patterns; established by monitoring the network during a known-good period; once baseline is established deviations become detectable: unusual protocols appearing, traffic spikes at unusual hours, new external IP connections, internal scanning activity, large data transfers to unknown destinations; baselining is essential for anomaly-based detection — without knowing what normal looks like you can't identify abnormal).

TOOLS

Traffic Analysis (examining network traffic patterns to identify security threats without necessarily reading content — combining packet capture flow data and log analysis; what to look for: scanning activity sequential connection attempts to many ports or hosts, beaconing regular periodic connections to external IPs at consistent intervals indicating C2 communication, data exfiltration unusually large outbound transfers especially to new or unusual destinations, DNS anomalies unusually long domain names high query volume to single domains indicating tunneling, lateral movement internal host connecting to many other internal hosts on management ports, protocol anomalies HTTP traffic on non-standard ports or unexpected protocols appearing, encrypted traffic to suspicious destinations unknown external IPs with high volume encrypted connections; tools: Wireshark for deep packet inspection of suspicious traffic, Zeek Bro for generating structured logs from traffic metadata, Security Onion complete network security monitoring platform integrating Suricata Zeek and other tools, Arkime Moloch for full packet capture indexing and search at scale, RITA Real Intelligence Threat Analytics specifically designed to detect beaconing and DNS tunneling in Zeek logs).

Wireshark in network monitoring context (beyond basic packet capture: display filters for security analysis — tcp.flags.syn==1 && tcp.flags.ack==0 shows SYN packets without ACK potential scan, http.request.method=="POST" shows POST requests where credentials and data are submitted, dns.qry.name contains "evil" filter DNS queries for suspicious domains, tcp.stream eq 5 follow a specific TCP conversation, frame.len > 1400 find large frames potential data exfiltration; Wireshark profiles: create custom profiles with saved filters column layouts and color rules for security analysis; Wireshark statistics: Protocol Hierarchy shows traffic breakdown by protocol, Conversations shows all communication pairs with data volumes, Endpoints shows all active IPs with traffic statistics, I/O Graph shows traffic over time for spotting spikes and patterns). tcpdump in monitoring context (lightweight CLI capture for production servers and automated monitoring; useful commands:

# Capture traffic and save for later Wireshark analysis
tcpdump -i eth0 -w /var/captures/$(date +%Y%m%d_%H%M%S).pcap

# Capture only SYN packets (detect port scans)
tcpdump -i eth0 'tcp[tcpflags] & tcp-syn != 0 and tcp[tcpflags] & tcp-ack == 0'

# Capture DNS traffic (detect tunneling)
tcpdump -i eth0 port 53 -w dns_traffic.pcap

# Capture traffic to/from suspicious IP
tcpdump -i eth0 host 185.234.218.42 -w suspicious.pcap

# Capture only large packets (potential exfiltration)
tcpdump -i eth0 greater 1000 -w large_packets.pcap

# Rotate capture files every hour (long-term monitoring)
tcpdump -i eth0 -w /captures/traffic_%Y%m%d_%H%M.pcap -G 3600

).
